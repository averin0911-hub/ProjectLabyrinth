# Основные сценарии тестирования алгоритмов

Код проверок: [tests/test_algorithms.py](../tests/test_algorithms.py).
Команды запуска и объяснение параметризации: [testing.md](testing.md).

Обозначения клеток: `0` — проход, `1` — стена, `2` — старт, `3` — выход.
Координаты имеют формат `(строка, столбец)` и отсчитываются с нуля.

## 1. Допустимый маршрут: test_valid_path

Для каждого из пяти алгоритмов создаётся отдельное поле:

```text
2 1 3
0 0 0
```

Из старта `(0, 0)` до выхода `(0, 2)` можно дойти только в обход стены.
Ожидаемая длина — 4 перехода. Проверяется, что:

- маршрут начинается в старте и заканчивается в выходе;
- `distance` и `steps` равны 4 и числу клеток маршрута минус один;
- в маршруте нет повторяющихся клеток;
- все клетки находятся внутри поля и не являются стенами;
- соседние клетки маршрута соприкасаются стороной;
- матрица лабиринта после поиска совпадает с копией до поиска.

## 2. Кратчайший путь: test_shortest_path

```text
2 0 0 3
0 1 1 0
0 0 0 0
```

От старта до выхода есть прямой путь длиной 3 и обход длиной 7.
Ожидается `distance == 3` и маршрут
`[(0, 0), (0, 1), (0, 2), (0, 3)]`.

Проверка выполняется для BFS, двунаправленного BFS, Дейкстры и A*.
DFS не участвует: он ищет допустимый путь, но не гарантирует кратчайший.

## 3. Путь отсутствует: test_no_path

На поле `[[2, 1, 3]]` стена отделяет старт от выхода.
Для всех пяти алгоритмов ожидается:

- `path == []`;
- `distance is None` и `steps is None`;
- непустые `visited_order` и `events`, чтобы можно было визуализировать
  выполненный поиск даже без найденного пути.

## 4. Старт совпадает с выходом: test_start_equals_end

Создаётся поле `[[2]]`, а в `solve()` явно передаётся `end=(0, 0)`.
Для всех пяти алгоритмов ожидается маршрут `[(0, 0)]`, длина 0,
список обработки `[(0, 0)]` и `visited_count == 1`.

## 5. Недопустимые координаты: test_invalid_coordinates

На поле `[[2, 1, 3]]` проверяются два ошибочных вызова:

| Аргумент поиска | Причина ошибки | Ожидаемый результат |
| --- | --- | --- |
| `start=(0, 1)` | Старт расположен на стене | `ValueError` |
| `end=(-1, 0)` | Выход расположен за границами поля | `ValueError` |

Оба вызова проверяются для каждого из пяти алгоритмов.

## Количество проверок

В файле пять тестовых функций. Благодаря параметризации четыре из них
выполняются по пять раз, а проверка кратчайшего пути — четыре раза.
Полный запуск набора содержит 24 проверки.
