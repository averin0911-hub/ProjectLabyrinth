# Тестирование алгоритмов

В проекте оставлены пять основных тестовых функций в
[tests/test_algorithms.py](../tests/test_algorithms.py). Они проверяют BFS,
двунаправленный BFS, алгоритм Дейкстры, A* и DFS на небольших лабиринтах
с заранее известным результатом.

## Запуск

Из корня проекта установите зависимости для тестирования:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -v
```

Если используете виртуальное окружение в Linux:

```bash
.venv/bin/python -m pytest -v
```

В Windows:

```powershell
.venv\Scripts\python.exe -m pytest -v
```

Один сценарий можно запустить отдельно:

```bash
python -m pytest tests/test_algorithms.py::test_no_path -v
```

## Что проверяется

| Тестовая функция | Проверка |
| --- | --- |
| `test_valid_path` | Маршрут обходит стену, соединяет старт с выходом, состоит из соседних проходимых клеток; матрица лабиринта сохраняется |
| `test_shortest_path` | При наличии короткого пути и длинного обхода выбирается кратчайший путь |
| `test_no_path` | При недостижимом выходе возвращается пустой путь, а данные поиска сохраняются для визуализации |
| `test_start_equals_end` | При совпадении старта с выходом маршрут содержит одну клетку и имеет длину 0 |
| `test_invalid_coordinates` | Старт на стене и выход за границами поля вызывают `ValueError` |

Подробные входные данные и ожидаемые результаты приведены в
[описании сценариев](test-cases.md).

## Как читать тесты

Каждый тест подготавливает лабиринт, вызывает `solve()` и проверяет результат
с помощью `assert`.

```python
maze = Maze([[2, 1, 3]])
result = BFS(maze).solve()
assert result["path"] == []
```

Здесь стена отделяет старт от выхода, поэтому путь должен быть пустым.
В матрице `0` обозначает проход, `1` — стену, `2` — старт, `3` — выход.
Координаты записываются как `(строка, столбец)`, начиная с нуля.
Длина пути — число переходов: маршрут из трёх клеток имеет длину 2.

`assert` проверяет условие. Если оно ложно, тест завершается с ошибкой.
Конструкция `with pytest.raises(ValueError):` проверяет, что вложенный вызов
сообщает о недопустимых координатах через исключение `ValueError`.

Декоратор `@pytest.mark.parametrize("algorithm", ALL_ALGORITHMS)` повторяет
одну тестовую функцию отдельно для каждого алгоритма из списка. Например,
`test_no_path` запускается пять раз, и каждый запуск имеет собственный
результат в отчёте.

## Почему получается 24 запуска

Четыре сценария выполняются для всех пяти алгоритмов: 4 × 5 = 20 запусков.
Проверка кратчайшего пути выполняется для BFS, двунаправленного BFS,
Дейкстры и A*: ещё 4 запуска. DFS исключён из этой проверки, поскольку
не гарантирует кратчайший путь.

Итого в наборе пять тестовых функций и 24 отдельных запуска. При успешной
проверке pytest выводит `24 passed`; затраченное время зависит от компьютера.

Набор проверяет перечисленные контрольные примеры алгоритмов. Проверки
генератора, консольного меню и остальных частей программы в него не входят.
Скорость поиска и расход памяти на больших лабиринтах оцениваются отдельно.
